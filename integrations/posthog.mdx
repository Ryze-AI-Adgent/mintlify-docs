PostHog connects with a **personal API key**. Once connected, the agent can read events, insights, and funnels, and run HogQL queries against the project you pick — putting product analytics next to your ads and SEO data in one answer. It can also make changes when you ask — see [What the agent can do](#what-the-agent-can-do).

## Step 1 — Create a personal API key

<Steps>
  <Step title="Open Personal API keys">
    In PostHog, go to **Settings → Personal API keys** and click **Create key**.
  </Step>
  <Step title="Choose its access">
    Grant read access to the projects you want, including the **Query** and **Insight** scopes. Read access is enough for reporting; add write access to the scopes the agent should change (for example insights or feature flags). Copy the key — it starts with `phx_`.
  </Step>
</Steps>

## Step 2 — Connect in Ryze

On the **Integrations** page, click **Connect** on the **PostHog** card and fill in:

- **Personal API key** — the `phx_` key
- **Host** — `https://us.posthog.com` for US Cloud, `https://eu.posthog.com` for EU Cloud, or your self-hosted URL

Click **Continue**, then pick the **Project** and click **Save**. The card shows **Connected** — click **View** to see the project name and change the **Project** later.

## What the agent can do

- **Read** — events, insights, funnels, dashboards, feature flags, cohorts and persons, plus HogQL queries
- **Change** — create or edit insights, dashboards, feature flags and cohorts when you ask
- **Delete** — remove those objects when you explicitly ask

By default the agent runs its tools on its own: the [**Tool approvals**](/agent/chat#tool-approvals) setting in the chat composer starts on **Skip all approvals**. To review changes before they happen, switch it to **Approve write & delete** (reads run freely, changes need approval) or **Manual approve** (every tool that touches your data needs approval). Scheduled tasks run without an approval step.

<Note>
To keep the agent read-only, give the personal API key read scopes only — PostHog then rejects any change.
</Note>

## Troubleshooting

- **Key rejected** — check the host matches where your account lives (US vs EU), and that the key has the Query and Insight scopes.
- **Project missing** — the key has no read access to that project. Edit the key's project access in PostHog and reconnect.
